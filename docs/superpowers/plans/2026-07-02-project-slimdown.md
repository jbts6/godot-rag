# 项目瘦身实施计划

## 概述

本计划基于技术设计文档，将项目瘦身分为3个阶段，共15个任务。目标是减少测试代码12-20%，源代码7-10%，同时保持100%测试通过率。

## 阶段1：源代码重构（优先）

### 任务1.1：拆分 search_eval.py 为 search_eval/ 包

**目标**：将863行的 search_eval.py 拆分为5个模块

**步骤**：
1. 创建 `rst2md/rag/search_eval/` 目录
2. 创建 `__init__.py` 公共接口
3. 迁移数据模型到 `models.py`
4. 迁移指标计算到 `metrics.py`
5. 迁移报告生成到 `reports.py`
6. 迁移基线管理到 `baseline.py`
7. 迁移评估逻辑到 `evaluation.py`
8. 更新所有导入路径
9. 运行测试验证

**验收标准**：
- 所有测试通过
- 公共接口不变（`from rag.search_eval import ...`）
- 每个模块行数在合理范围内（80-250行）

### 任务1.2-1.7：创建各个子模块

**目标**：创建 models.py、metrics.py、reports.py、baseline.py、evaluation.py

**步骤**：
1. 从 search_eval.py 提取相关代码
2. 添加必要的导入
3. 确保模块间依赖正确
4. 运行测试验证

**验收标准**：
- 模块职责单一
- 代码行数在合理范围内
- 测试通过

### 任务2.3：合并重复的report测试

**目标**：合并23个report相关测试中的相似测试

**步骤**：
1. 分析report测试的相似性
2. 合并可参数化的测试
3. 运行测试验证

**验收标准**：
- 测试数量减少
- 测试通过

### 任务2.4：迁移 test_rag_search.py 到 pytest 风格

**目标**：移除类定义，简化断言

**步骤**：

**验收标准**：

## 阶段4：验证与收尾

### 任务4.1：运行完整测试套件

**目标**：确保100%通过率

**步骤**：
1. 运行 `uv run pytest -q`
2. 检查测试结果
3. 修复任何失败

**验收标准**：
- 所有测试通过
- 无失败或错误

### 任务4.2：检查测试覆盖度

**目标**：确保覆盖度不变

**步骤**：
1. 运行 `uv run pytest --cov=rst2md/rag`
2. 比较重构前后的覆盖度
3. 确保覆盖度不低于重构前

**验收标准**：
- 覆盖度不低于重构前
- 无覆盖度下降

### 任务4.3：更新文档

**目标**：记录新的测试结构和重构指南

**步骤**：
1. 更新 README 或相关文档
2. 记录新的测试结构
3. 提供重构指南

**验收标准**：
- 文档完整
- 易于理解
- 便于团队参考

## 执行顺序

1. 阶段1：源代码重构（任务1.1-1.7）
2. 阶段2：测试代码优化（任务2.1-2.4）
3. 阶段3：项目结构优化（任务3.1-3.3）
4. 阶段4：验证与收尾（任务4.1-4.3）

## 风险与缓解

### 风险1：重构引入bug
**缓解**：逐步重构，每步运行测试

### 风险2：测试覆盖度下降
**缓解**：重构前记录覆盖度，重构后验证

### 风险3：团队适应成本
**缓解**：提供重构指南，逐步引入新结构

## 成功指标

1. 测试代码减少15%以上
2. 源代码减少7-10%
3. 测试通过率保持100%
4. 覆盖度不低于重构前
